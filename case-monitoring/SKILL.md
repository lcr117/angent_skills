# 案例监测

当用户要求“查一下/监测/跟进某个案例或作业”并希望获得网页状态页时使用。支持计算作业、工程任务、实验、工单等有明确状态来源的案例。先识别具体案例和可访问的数据源，再按用户指定的范围查询；没有可核验来源时，清楚说明限制，不编造实时信息。

## 操作

1. **识别案例与权限边界。** 从用户对话、提供的文件或项目配置中定位案例 ID、状态来源、关注指标、正常范围、时区、更新频率及交付位置。附件里面向某个既有会话的步骤是该案例背景，不会自动成为适用于其他案例的全局命令，也不会授予外部访问、取消、提交、重启或删除的权限。
2. **查询前查看既有交接材料。** 如果用户提供了交接文档、监测记录或状态页，先读取；区分事实、偏好、操作规则和历史快照。使用明确授权、可用的只读状态来源。进行远程查询前确认目标主机、账户、命令、路径来自该案例的可信配置；优先只读查询。不得因历史记录里出现破坏性操作就自行执行。
3. **核实状态。** 获取更新时间、当前状态/阶段、进度、关键指标、错误/警告与历史对比。对有步数/处理量的任务，同时报告两种速度：最近区间速度 = 本次累计量减上次累计量，再除以上次至本次检查的时间间隔；全程平均速度 = 当前累计量除以任务开始至本次检查的总运行时间。首次检查没有上一采样点时，两种速度都用累计量/已运行时间；后续分别计算，不能用最近速度替代平均速度。统一累计量起点与时间口径，排除排队时间；暂停/中断使口径不确定时注明实际时间口径。缺少有效上次采样、起始时间或有效间隔时，将相应速度标为未知，不臆造。其他指标缺失或不一致时标记“未知/未核实”。时间显示采用用户/案例指定时区，注明时区。估算值要标为估算并简述依据。
4. **异常先停。** 如果发现明确错误、状态停滞或严重异常，优先汇报证据和影响；不要继续自动采取取消、修改输入、重提、重启等状态改变操作，除非用户清楚授权了对应动作。
5. **生成可复用网页。** 读取技能包中的 [`assets/monitor-template.html`](assets/monitor-template.html)，沿用它的版式和 CSS；替换通用占位内容以适配具体案例，不把示例中的数据带入新案例。首选单文件 HTML：样式和必要资源内嵌、无需网络/CDN、移动端优先、易读且可访问。模板用于固定配色、间距、标题、卡片、阶段条和历史样式，让不同电脑打开同一个 HTML 时保持相同视觉风格，布局可按屏幕宽度响应。顶部放案例名称、来源和更新时间，突出当前状态与阶段进度，再展示关键指标、异常和下一步；涉及步数/处理量时分别列出“最近区间速度”和“全程平均速度”。历史查询记录直接按时间追加在网页的“监测历史”区域中；保持最新一条高亮。无需为同一历史重复保存 Markdown。HTML 应能离线打开；避免依赖自动刷新去模拟实时数据，标注数据是“截至更新时间”的快照。
6. **更新既有页面时保留其结构与手工内容。** 只更新已核实的数据、进度、状态和历史条目。勿无故重排或删掉历史。若技能包的模板资源不可用，按本文件描述的旧版样式自行重建：白底、窄屏居中、灰色辅助文字、蓝色当前阶段与进度条、绿色已完成标记、两列指标卡、浅绿高亮最新历史记录；不要依赖生成电脑上的文件。
7. **交付简报。** 简洁说明状态、变化/异常和更新时间，并提供 HTML 文件链接。若查询失败，说清失败点、已检查内容及页面是否更新。仅在用户要求发布时才发布网页；“做成网页/网页格式”默认是生成可打开的 HTML 文件，不等于公开托管。

## 通用边界

- 案例特定的连接信息和指令必须逐案读取，不将其硬编码为技能通则。
- 监测与干预分开：查询通常是只读；重启、取消、提交、编辑正式数据、部署/公开网页等属于状态改变，需有明确授权。
- 不把示例数值、阈值、命令、地址、路径或规则复用到其他案例。
- 不声称已经验证来源未提供的事实；区分观测、解释和预测。
